# Domain documentation

This repository uses a single-context layout.

Before exploring a domain:

- Read the root CONTEXT.md.
- Read relevant decisions under docs/adr/ when present.
- Follow AGENTS.md and the relevant feature requirements.

Use the glossary's vocabulary in tickets, specifications, and tests. Surface conflicts with existing ADRs explicitly.

Proceed when optional domain documents are absent; create new domain documentation only when terminology or decisions require it.
